# Car Workshop POS 安全与质量审计报告 — v0.3.6

**审计基线：** v0.3.5（用户提供的 ZIP）  
**交付版本：** v0.3.6  
**审计日期：** 2026-11-12

## 1. 执行摘要

v0.3.5 已具备工单、客户/车辆、库存、收银、供应商单据、报表、员工权限及 MyInvois 流程。现有安全措施包括 HMAC 签名会话、HttpOnly/SameSite Cookie、密码重置使旧会话失效、API Origin 检查、上传文件 magic-byte 检查、老板权限守卫及 SQLite 快照备份。

本次发现并修复一项明确的访问控制问题：**二维码生成 API 原本不要求登录，且返回结果可被公共缓存**。二维码内容可能包含发票验证链接或店内网络地址；即使页面本身需要登录，仍可直接请求 `/api/qr`。v0.3.6 已加入登录验证，并将缓存策略改为 `private, no-store`。

**整体判断：** 可作为单店本地/LAN POS 继续测试；本次静态审计不等同正式生产环境或税务合规认证。

## 3. 发现与建议（按优先级）

### P1 — 正式上线前应处理

1. **登录失败锁定是单进程内存状态。** `src/lib/auth.ts` 的锁定在重启时清空；多实例也不会共享计数。若未来服务器化，建议迁移到 SQLite 持久化限流或共享存储。
2. **金额使用 JavaScript/SQLite Float。** 工单、付款、库存成本、SST 等金额字段多为 `Float`，存在浮点精度风险。建议在独立迁移版本改为整数 sen（RM 1.00 = 100）或 Prisma Decimal，并制定历史数据迁移及对账方案；不可直接改 schema 而不迁移数据。
3. **MyInvois 正式环境签名/证书流程需核实。** 设置界面已说明未内置数字签名/正式环境风险。需按 LHDN 当前规范验证认证、证书保管、签名、撤销、重试及审计追踪；静态代码检查不能替代官方合规确认。
4. **数据库与上传文件备份需做恢复演练。** 已有 SQLite 快照与 uploads 备份逻辑，但仍需在隔离副本验证恢复步骤、文件完整性、保留策略及异机拷贝。备份成功不等于恢复已验证。

### P2 — 建议尽快改善

5. **公开顾客 e-Invoice 表单限流为内存级。** `tooManyRequests()` 按 token 限制请求，但重启会清空，多实例不共享。建议持久化限流并记录异常提交事件。
6. **输入与业务规则需统一。** 多处前端使用 `parseFloat`；应在 API 层统一使用 Zod 校验有限数值、范围、精度、非负规则及状态转换，不能只依赖 UI。
7. **关键流程需要自动化测试。** 优先覆盖工单→库存→完工→开票→收款/退款→贷项通知；现金班次；员工/老板权限；备份/恢复；MyInvois 提交、轮询及重试。
8. **安全头与部署网络边界需回归。** 当前中间件设置 CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy 和 API Origin 检查。需在 Electron、LAN 手机、打印、OCR、QR 和 MyInvois 场景验证。

### P3 — 后续产品改善

9. 增加库存盘点/调整审批与低库存补货报表。
10. 增加操作审计日志：记录价格修改、作废、库存调整、退款及税务设置变更。
11. 增加每日自动备份状态、最近备份时间、失败提醒及恢复指引。
12. 增加发布前 CI：依赖安装、ESLint、TypeScript、Prisma schema 校验、构建及关键 API 测试。
